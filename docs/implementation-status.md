## Propertyと独立検証

例の「10万円なら2段承認」に対する全金額1段実装は単調性を満たすが要求違反である。
「順序どおり」に対して逆順承認と同数ログを出す実装も、ログ件数の一致だけでは拒否できない。
本文/要求Specテンプレートは直接対応する性質へ修正した。単調性・ログ完全性は別の補助性質/要求とする。

別コンテキスト、テスト改変検査、hold-outは監督を分離するが、現行 Hook は対象の直接操作だけを拒否し、
Bash・Grep 等を含む全経路の不可視性を保証しない。同じ要求の誤りを共有する可能性も残る。
要求原典との照合と業務担当の受入れを別に行う。サンプルの成功を大規模案件へ一般化しない。

## 生成物を確認する条件

元コミット（未コミットなら内容ハッシュ）、参照元、生成方式/版、確認者・結果を残す。
機械抽出は抽出規則の範囲、LLM記述は意味と網羅性、組立/変換は元データと表示を確認する。
元データが変わったら影響部分を未確認とし、再生成・再レビューする。
過去のケーススタディ・議論は当時の記録として残し、現行の保証範囲には本書と本文を用いる。

局所の合成判定器・Plugin検査・文書変換の実施範囲は[ローカル検証結果](local-validation.md)を参照。実モデル比較・実PJ・実行経路の強制は未検証。
