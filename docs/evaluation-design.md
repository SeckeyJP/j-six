# 評価指標・総コスト・比較条件

J-SIX の補足資料。著者提案の計測設計であり、改善効果の実測値ではない。現段階では企業の実PJに適用せず、ローカルの題材と合成データで検証する。人間不参加の実験から顧客承認・複数社運用・H-4の成立を主張しない。

## 測定単位と固定条件

開始前に実験ID、対象commit/入力/要求/期待値のハッシュ、全投入タスクID、方式、モデルの提供名と取得日、実行設定、検査版、資源/時間/金額上限、打切り時刻、再試行・回復手順を固定する。変更した条件は別群にし、都合のよい実行だけを選ばない。実行記録のひな型は [run-record.json](../templates/evaluation/run-record.json)。nullは未測定・未確定であり0ではない。秘密・個人情報や生プロンプトを公開記録へ転記せず、アクセス管理された参照とハッシュを使う。

タスクは成功・失敗・打切り・未着手のいずれかを観測期限時点で記録する。成功は事前の受入条件をすべて満たし、対象版と証拠を確認できる場合に限る。試行は別行にし、失敗後成功も全試行を費用に含める。完了率の母数は割当済み全タスク（未着手を含む）、費用はその全試行と共通費用。異なる完了件数・品質の群の総額だけを比べて効率向上と言わない。

## 指標と分母

| 指標 | 記録・計算 | 判定上の限界 |
|---|---|---|
| 完了率 | 受入済みタスク数 / 割当済み全タスク数 | 母数0は未定義。失敗・打切り・未着手を別掲 |
| 欠陥・流出 | 事前定義の重大度別件数、受入後発見件数、観測期間 | 未観測を0にしない。少数・短期間の0件は無欠陥を保証しない |
| 要求充足 | 全要求IDごとに対象版、テストリンク、実行結果、期待値の独立確認、意味上の充足、未検証理由 | ID出現率と意味上の充足率を別集計。未検証も全要求の母数に残す |
| 見逃し率 | 独立に固定した停止すべきケースを許可した件数 / 停止すべきケース数 | 正解不明のケースを分母から外した数も併記。分母0は未定義 |
| 誤停止率 | 独立に固定した許可すべきケースを停止した件数 / 許可すべきケース数 | 合成ケースの分布を実案件の発生率と解釈しない |
| 再作業 | 修正・再検証等の実時間と理由、全実時間に占める割合 | 再作業は各作業区分の内数。二重加算しない |
| 人間負荷 | 承認・照合・台帳保守・調整・復旧の回数と実時間、待ち時間 | AIによる役割模擬は人間実測ではない。待ち時間と労働時間を別記 |
| 従来指標 | バグ密度、レビュー密度、カバレッジ、変異検査等の定義・母数・ツール版 | AI生成量の増大で意味が変わる代理指標。従来の基準値だけで受入を決めない |

要求・リスクに基づく品質/受入条件は維持する。旧来のKS当たり密度や削減率を満たすために条件を緩めない。基準値は同じ欠陥分類・対象版・観測方法の比較データを蓄積して見直す。少数例から業界共通の新基準を設定しない。要求リンク・意味・未検証の内訳は[検証戦略](adoption-and-verification.md)と対応させる。

## 総コスト

費用の通貨と観測期間を統一する。為替が必要なら出典・取得日・換算レートを保存する。

- 実時間H = 要求 + 設計 + 実装 + 検証 + レビュー + 移行 + 教育 + 管理 + 例外復旧。1人の同じ時間を複数区分に入れない。並行する別人の作業時間は各人分を合算する。
- 労務換算費L = Σ（各人・区分の実時間 × 対応する仮定または実際の時間単価）。共通教育・運用費は配賦方法と対象期間を明記する。
- ツール等費T = 座席費 + API従量費 + CI/実行環境費 + 保存費 + その他の増分支出。含まれる利用を二重計上しない。
- 総換算費C = L + T。完了当たり費用 = C / 受入済み件数（0なら未定義）。
- 工数余力 = 比較元H − 比較先H。同一の成果・品質条件で解釈する。換算費差 = 比較元C − 比較先C。
- 現金支出差 = 実際に減った支出 − 新たに増えた支出。固定給与の時間削減を、そのまま支出削減にしない。現金ROIを示すなら実際の便益・増分投資・対象期間を別途定義する。

座席方式は席数×期間×単価と利用上限、API方式はモデル別の入力/出力/キャッシュ等の請求単位×単価を記録する。両方式は別シナリオとして試算する。併用はどの試行が座席に含まれ、どれがAPI追加課金かを対応付ける。失敗・再試行も課金対象なら含める。上限待ち・承認待ち・キュー待ちは経過時間として記録し、実際に人を拘束した時間だけを排他的な実作業区分へ計上する。待ち時間を一律に労務費へ加算しない。

価格・利用制限は変わる。2026-09-26に確認した公式の[Maxプラン](https://support.claude.com/en/articles/11049741-what-is-the-max-plan)、[Claude Codeの利用枠](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)、[API料金](https://platform.claude.com/docs/en/about-claude/pricing)を参照し、測定開始時に再確認する。定額座席を無制限の並列実行費として扱わない。[計算例](evaluation-example.md)の円単価は公式価格ではなく仮定値。

## 比較方式と中止条件

Plugin単独、Plugin＋必須CI・PR承認、Hub相当の3方式を比べる。既存ツールで実現できる検査をHubだけに与えない。同一タスク・要求・モデル・検査内容・計算資源・予算・期限・再試行条件で、統制の置き場所と状態管理による差を観測する。Hub相当のローカル判定器を用いる場合、管理された実行環境や実Hubの強制力を実証したとは書かない。

1. 合成判定比較: 固定した入力と正解に対する許可/停止を測る。実AIの振る舞い・人間負荷・業務効果は対象外。
2. 実AI実行比較: 実際のモデル呼出し、全入力・出力参照、試行順、費用、失敗・回復を記録する。同じモデルでも非再現性があるため、順序の均衡化と複数試行を事前に決める。実行不能なら未実施と記録し、合成値で代用しない。
3. 人間・組織の比較: 現段階では実施しない。H-4の承認負荷・責任分担・企業適用は未評価のまま残す。

予算・期限・許可範囲を超えたら打切りとし、結果を消さない。見逃し/誤停止の期待値は判定器実装前に固定し、実装者の都合で書き換えない。方式間の差は件数・分母・個別例とともに報告し、小標本の結果に統計的一般化を与えない。[Hubの評価計画](control-plane/concept.md#7-仮説と評価計画)におけるRQ2は対応の存在と意味を、RQ4はツール費と人間の実作業・待ちを分けて扱う。
