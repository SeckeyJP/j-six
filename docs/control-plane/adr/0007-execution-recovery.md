# ADR-0007: 実行要求を先に記録し、結果不明時は照合してから復旧する

## ステータス

提案中（著者提案。実行基盤では未実装・未検証）

## 日付

2026-09-23

## コンテキスト（背景）

Git から工程状態を再構築できても、外部で起動したコンテナや作成した PR の結果までは確定しない。
起動後・記録前の障害で同じ仕事を再投入することや、古い承認で再開することを防ぐ必要がある。

## 判断（Decision）

Git を正本とする D1 を維持し、外部作用より前に実行要求を保存する。実行基盤は次の記録・手順を満たす。

| 項目 | 内容 |
|---|---|
| run ID | タスクの実行試行の安定した識別子。再送で変更せず、やり直しの新試行では新しく発行 |
| command ID | 起動・PR 作成・取消し等、1つの外部操作の識別子。再送では同じ ID |
| 要求 | 対象成果物・方針・検査・承認・許可への参照、投入主体、前提状態、操作種別 |
| 結果 | 外部の実行 ID・PR ID、対象のハッシュ、状態、時刻、発行元、要求との対応 |
| 復旧記録 | 照合した外部状態、判断者、取消し・部分完了・失効、後継試行への参照 |

1. 最新の対象・許可・失効と前提状態を確認する。Git の記録先 ref の期待 SHA を条件に要求を追記し、競合時は読み直して再判断する。保存を確認できなければ送信しない。
2. 記録済み command ID で実行サービスへ要求する。サービスが冪等性キーを提供する場合も、その保証範囲を確認する。同じ ID の要求を複数の制御処理が別々に実行できないよう、実行側の所有権と世代番号を検査する。
3. 応答・成果物・PR ID を要求に結び付けて Git に追記する。途中で応答を失ったら `unknown` とし、外部実行を照合するまで完了や失敗と決めない。
4. 再起動時は Git の未確定要求を読み、run ID / command ID で外部実行、成果物、PR を検索する。既に完了していれば既存結果を検証して記録する。確実に未実行なら同じ要求を再送する。複数候補・検索不能・不一致なら隔離して運用判断を待つ。
5. 新しい試行を始める場合は、前試行の停止または影響範囲を確認し、前試行を参照した新 run ID と新しい許可を発行する。状態不明のまま新試行へ進めない。

外部サービスに冪等性・照合・旧実行の排除がない場合、Git の記録だけで exactly-once を保証しない。
その操作は自動再送の対象外とし、状態確認が終わるまで保留する。実行器の一時的な状態は照合対象であり、独立した承認正本にはしない。

### 状態と部分完了

| 状態 | 次の処理 |
|---|---|
| requested | 要求が Git に保存済み。許可を再確認して送信 |
| running | 実行 ID を確認済み。結果または取消しを待つ |
| unknown | 外部作用の成否不明。新規投入・結果取込みを止める |
| reconciling | 外部状態と照合中。記録と外部が一致するまで進めない |
| completed | 対象が一致する結果を Git に保存済み。受入れ可否は最新の許可で別途判定 |
| cancel_requested | 取消し要求を保存・送信。停止済みとは表示しない |
| cancelled | 停止と既発生の作用を確認・記録済み。遅着結果を反映しない |

コード生成成功・PR 作成失敗なら、同じ成果物に対する PR 作成だけを照合・再送する。コード生成をやり直さない。
PR 作成成功・応答消失なら既存 PR を run ID と対象で照合し、重複作成しない。
承認保存の応答消失では、記録を読み直して対象・権限・保存を確認するまで工程を進めない。
緊急失効は ADR-0006 に従い、取消し要求と結果隔離を実施する。取消しは既に行われた外部作用の自動巻戻しを意味しない。
記録は追記し、現在の状態はその記録から再構築する。

## 理由（Rationale）

先行記録と安定した識別子があれば、応答の再受信・再送と新しい実行を区別できる。外部状態との不一致を隠さず、復旧の判断を監査できる。

## 検討した代替案

| 代替案 | メリット | デメリット | 却下理由 |
|---|---|---|---|
| 実行後だけ記録 | 書込み回数が少ない | 起動済みを見失う | 二重投入の原因になる |
| タイムアウトを常に失敗扱いして再実行 | 回復が速い場合がある | 実行中・完了済みを重複実行する | 結果不明と失敗を混同する |
| Git の再生だけで復旧完了とする | 構成が単純 | 外部の部分完了が分からない | 読取りモデルの復旧と実行復旧は別 |

## 影響（Consequences）

### ポジティブな影響

要求・実行・PR・承認の各境界で障害を注入し、期待状態を確認できる。

### ネガティブな影響（トレードオフ）

記録の競合処理と外部サービスごとの照合・取消しが必要。結果不明時は可用性より誤った再実行の防止を優先する。

### 将来の注意事項

試作の受入条件は、起動・PR 作成・承認保存の直前直後、記録の応答消失、重複応答、同時復旧、失効後の遅着結果で、二重実行や古い許可による反映がないこと。Git の ref 更新方式と実行側の世代確認は実装前に決めて検証する。
