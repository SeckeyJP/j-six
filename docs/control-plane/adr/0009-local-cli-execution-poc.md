# ADR-0009: 単一 PC の中央実行 PoC ではローカル CLI を選択起動する

## ステータス

提案中（単一 PC・合成入力の PoC 設計。実装・実証前）

## 日付

2026-09-27

## コンテキスト（背景）

将来の Hub はタスクごとのコンテナで CC と J-SIX Plugin を動かす構想である（[ADR-0005](0005-central-execution-with-local-fallback.md)）。まずは個人の PC と既存の Codex／Claude Code のサブスクリプション利用枠で、投入・判定・証跡・受入れを通す小さな PoC を試したい。現行の静的リプレイはこの処理を持たない。開発者 API キーや SDK による従量課金はこの PoC の実行経路に含めない。

## 判断（Decision）

- この PoC は **単一 PC・単一利用者・公開または合成 fixture** に限定する。Hub のローカル制御プロセスが run ID、対象、方針版、許可範囲を固定し、非公開 Git の記録 ref に許可と実行要求を保存・再読込で確認してから、run 専用 Git worktree で `codex exec` または `claude -p` の一方を子プロセスとして起動する。両 CLI の保存済みサブスクリプション認証を使い、実行前に方式・上限・追加クレジット設定を再確認する。不明なら投入しない。
- D7 の **PoC 限定例外** として、run ごとに人間が選んだ CLI を起動する最小 adapter を置く。モデル間の自動振分け、討論、最適化、代替モデルへの自動フォールバックは作らない。プロセスの Phase・Gate、D1 の Git 正本、D3 の依存方向は変えない。
- 作業 AI は候補だけを作る。Hub の判断処理は検査結果や人間承認を自分で発行せず、有効な方針・独立検査・人間の確認記録の対象と版を照合する。候補 ref と記録 ref は分ける。結果が `unknown`、記録保存失敗、版の競合、失効、必須検査の欠落なら、取込みと新規投入を保留し照合する（[実行契約](../execution-contract.md) R1〜R8、[ADR-0007](0007-execution-recovery.md)）。Git の追記だけで exactly-once を保証しない。
- この PC の同一 OS ユーザーで動くため、worker から記録先や認証 cache へのアクセスを強制的に遮断できるとは主張しない。本人認証済み承認、証跡の改ざん耐性、Hub 外の CLI 操作の阻止、複数主体の責任分界、企業実 PJ の適用はこの PoC では検証しない。適合性の主張は、Hub が管理した run と、その候補の受入れ制御に限定する。
- PoC の「許可」は合成 fixture を実行するローカル試験の判定であり、実行契約 R1 の署名・発行者権限や R5 の本人確認を満たした正式な工程許可ではない。これを J-SIX Phase/Gate の承認済み状態へ読み替えない。R1〜R8 の実装済み範囲と未証明範囲は Hub 側 Spec に対応付ける。
- PoC のコードと仕様は `j-six-hub` に置く。現行の公開 Pages リプレイとは別のローカル経路と表示を用い、リプレイを実行基盤として説明しない。J-SIX 本体は Hub に依存しない。

## 理由（Rationale）

既存のローカル認証を利用しつつ、Hub の判定を CLI 実行の前後に置く最小の縦断検証ができる。作業場所が同じ PC でも Hub 管理下の投入は ADR-0005 の「ローカル退避」と異なる。検査・承認の真正性と実行経路の強制は、この構成だけでは証明できないため、結果の表示と評価を限定する。

## 検討した代替案

| 案 | 利点 | 今回採用しない理由 |
|---|---|---|
| 開発者 API／Agent SDK で実行 | 統合しやすい | サブスクリプション枠だけで PoC を回す条件から外れる |
| CLI を人間が直接起動して結果だけ回収 | 構成が軽い | Hub の投入前許可・要求保存・復旧を検証できない |
| 最初からコンテナ・複数主体で実行 | 強い隔離を検証しやすい | 単一 PC の初回 PoC として範囲が大きい |

## 影響（Consequences）

PoC は CLI の版・認証・非対話権限と利用枠の変動を起動前に確認する必要がある。Git 記録と候補の競合処理、`unknown` の照合、独立検査を省けない。合成 fixture での成功は将来構想の性能・ROI・複数ベンダーへの適用を裏付けない。実行経路を制限できない環境での強制力は、候補取込みの範囲にとどまる。
