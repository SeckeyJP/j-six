# ケーススタディ #3 — J-SIX で J-SIX Hub のサンプルを作る

**Author**: H.Sekita | **Date**: 2026-09-22 | **題材**: [j-six-hub](https://github.com/SeckeyJP/j-six-hub)（リプレイ型サンプル）

> 決定事項 D9「Hub 自体を J-SIX で開発する」に基づき、J-SIX Hub の構想を説明するための
> Web アプリを J-SIX の手順で作った記録である。ケーススタディ #1・#2 が既存のサンプルに対する
> 実測だったのに対し、本稿は **J-SIX を新しい題材に最初から適用した記録**である。
>
> 本稿は工数削減や品質向上を主張しない。**記録から実測できたことと、そこで分かった限界**を書く。

## 3. 分かったこと

### 3.1 受入条件が設計の抜けを見つけた

実データで受入条件 AC-005（「設計レビュー後の Phase 逆戻りで、P1 以降が進行中に戻る」）を検証したところ、
**逆戻りの直後に P4 が「完了」に戻ってしまう**不具合が出た。前の周で合格したタスクが残っていたためである。

- 規則を「per_task の Phase は、**開き直した後に投入したタスク**で判定する」と補い、Design Spec に追記した
- 単体テストだけでは気づけなかった。**実データの受入条件**が設計の穴を突いた例である

### 3.2 テストが通っても、画面は壊れていた

154件のテストが通った状態で公開したが、再生すると画面が上下にがたついた。
ブラウザで160件を1件ずつ進めて位置と大きさを測ったところ、次が判明した。

| 要素 | 測定値（修正前） |
|---|---|
| 「いま起きたこと」の高さ | PC 9通り（79〜199px）、スマートフォン 37通り |
| 再生スライダーの幅 | 10通り |
| 案件カードの高さ | 11通り |

- 原因は、出来事ごとに文の行数が変わり、その下の要素が押し動かされることだった
- jsdom のテストでは高さを測れない。**実際のブラウザで測る**工程を加えて初めて分かった
- 対策後は、測定したすべての要素が1通りになった。要求に REQ-022（再生中に配置が動かない）を追加した

### 3.3 修正が別の不具合を生んだ

「速度」の表示が2行に折り返す問題を直した結果、**スマートフォン幅で横スクロールが出た**（390px の画面で 401px）。
公開ページで測って初めて気づいた。狭い画面の検査を、計測手順に加えた。

### 3.4 自分で決めた規約から外れた

M3（リプレイ用データ）の作業では、CLAUDE.md に書いた「Red → Green を別のコミットにする」を守らず、
テストと実装を同じコミットに入れた。PR に記録し、以降のタスク（TASK-HUB-001〜013）では分けた。

- 13タスクのうち、Red / Green を分けたのは 11タスク
- 分けなかったのは、CI の追加（006）とデータ抽出（007・012）である。前者はテストの対象が無く、
  後者はツールのテストと実装を同じコミットに入れた

### 3.5 要求の追加は、統制の観点では「テストが無い状態」を作る

J-SIX Hub の題材（approval-workflow の実行記録）でも、本稿の開発でも、同じことが起きた。
Spec に要件を足した瞬間、その要件にはテストが無い。J-SIX の品質ゲートはこれを検出して作業の完了を止める。

- 題材の記録では、要件追加の直後に**15回連続でブロック**された（当時の Plugin の不具合も重なった）
- 本稿の開発では、先にテストを書いてから実装する手順のため、この状態は各タスクの数分で解消した

## 4. 限界

- **1日・1名・1題材の記録**である。一般化できない
- 作ったのは**実際の AI を動かさない**サンプルである。Hub 自体は実装していない
- リプレイ用データの 76 / 176 件は再構成であり、うち 40 件は架空の案件である
- 工数は比較対象（人手のみの実装）が無いため測っていない。効果は主張しない
